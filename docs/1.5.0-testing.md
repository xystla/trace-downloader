## What changed in 1.5.0

The full list is the `## 1.5.0` section of `CHANGELOG.md`. In short:

- **Downloads** (`src/trace_grabber/pieces.py`, `space.py`, `gui/worker.py`): a full game is fetched as two-second pieces into a hidden `.…pieces` folder and joined when complete, so a stopped or interrupted download resumes. Time left, a disk-space check before starting, choices for what automatic downloads fetch and how often, and reordering the waiting line.
- **Watching** (`gui/web/app.js`, `src/trace_grabber/bookmarks.py`, `highlights.py`): speed, frame-step, keyboard shortcuts (press `?`), full screen, reopening where you stopped, bookmarks on the match timeline, and clip export to `My Clips`.
- **Library** (`src/trace_grabber/library.py`, `found.py`, `naming.py`): a Storage page, removal to the Trash (Mac only for now), a "Video missing" card with Download again / Find it…, and a file-name pattern in Settings.
- **Polish** (`gui/app.py`, `gui/tray.py`, `platform_tasks.py`): a notification when the Trace login expires, a status line in the tray menu, Copy stats and Copy image on a game's page.

## Windows checklist

None of this could be run on the Mac where it was written. Tick each off, and note anything odd.

**Downloads**
- [ ] Start a full game. The row reads like `12% · Half 1 · 8.4 MB/s · about 14 min left`.
- [ ] Stop it. The row and the card offer Resume and Discard. Resume starts near where it stopped.
- [ ] Stop, quit TraceDown, reopen. The card still offers `Resume (N%)`.
- [ ] Let one game finish. It plays to the end of both halves with sound in sync, and no `.pieces` folder is left in its `Full Game` folder (hidden files shown).
- [ ] The Downloads page shows free space. With two games waiting, the move up/down arrows work.

**Watching** (open a saved game's own page)
- [ ] `K`/space, `J`/`L`, `,`/`.`, `<`/`>`, `M`, `?` all work.
- [ ] `F` fills the screen; arrows skip 5 seconds; `B` shows "Bookmarked …" over the picture; `Esc` leaves.
- [ ] `B` outside full screen opens a note field; typing letters such as `k` does not pause the video; Enter saves; the flag appears on the timeline.
- [ ] `I`, `O`, Export clip: the clip lands in the game's `My Clips` folder and plays.
- [ ] Watch past 10 seconds, go back to all games, reopen: "Resumed at …".
- [ ] Clicking a timeline mark while paused stays paused; while playing keeps playing.

**Library**
- [ ] Storage page shows sizes, has **no Remove buttons**, and says removal isn't available on Windows yet. Discard on an unfinished download still works.
- [ ] Move a saved game's video elsewhere, refresh: the card says the video is missing. Find it… → pick the file → Watch Game works. The file is not moved.
- [ ] Settings → File name for full games: type `{team} vs {opponent} {date}`, check the example, download a game, check its name.

**Polish**
- [ ] Copy stats, paste into Notepad: a headline, one line of numbers, and a table.

- [ ] With automatic downloads on, the tray menu's first line says what is downloading or when it last checked, and the menu behaves normally if it is open while a download runs.
- [ ] If the Trace login is expired when a check runs: one notification, a "Reconnect to Trace…" item in the tray menu, and the window shows the Reconnect banner.

## Removal on Windows: not switched on yet

`platform_tasks.trash()` refuses on Windows and `can_trash()` returns False, so the Storage page offers no removal there.

**Why:** the usual way to send something to the Recycle Bin from a script (`Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile/DeleteDirectory` with `SendToRecycleBin`) deletes for good, without asking, when the drive has no Recycle Bin (network shares, most USB sticks and memory cards) or the item is bigger than the bin's limit. A game that can no longer be downloaded from Trace must never be lost that way.

**Before switching it on**, write the Windows branch of `_trash_one` and prove, with throwaway files only, on each of:

1. the main drive,
2. a USB stick or memory card,
3. a network share,
4. a folder larger than the Recycle Bin's size limit,

that the result is always one of: the item is in the Recycle Bin and can be restored, or the call fails with an error and the item is still where it was. If any case ends with the item simply gone, it is not safe. A hidden process must also never be left waiting on a dialog nobody can see (give the call a timeout).

Only then make `can_trash()` return True on Windows, and update the changelog line that says removal isn't offered there.

## Known small issues, left for later

- Stop can take up to 30 seconds on a stalled connection.
- The space check asks for more room than needed when halves are combined (about 11.8 GB for a 4.5 GB game).
- A disk that fills mid-download shows the raw system error.
- In full screen the control bar never hides.
- After picking a speed or a source with the mouse, shortcuts don't work until you click elsewhere.
- Stopping in the last 30 seconds of the first half forgets the position.
- While a download runs, a newly opened game page gets its timeline only when the download ends.
- A loose older video named `…vs-rovers-2.mp4` can be taken for either "vs Rovers" or "vs Rovers 2".
- Any `.mp4` dropped into a game's `Full Game` folder is treated as the game.
- "Last checked today…" in the tray can be stale after the computer sleeps overnight; the tray says "Checking…" while highlights and recaps download.
- A hung Windows clipboard call would leave the Copy button disabled (no timeout yet).
